# UPDATES

Заметки по улучшению viperr, найденные при интеграции в gateway (2026-11-25).

## 1. Получить одну переменную без структуры

Сейчас нет способа прочитать одиночный ключ по полной цепочке источников
(process > .env > xml > default) — только через объявление структуры с тегом.
`ProcessEnv().Lookup(key)` смотрит лишь в окружение процесса.

Хотелось бы что-то вроде:

```go
v, ok := viperr.Get("HTTP_PORT")            // по цепочке источников
v, ok := viperr.Get("HTTP_PORT", "8080")    // или с default
```

Кейс из gateway: точечно прочитать `GATEWAY_API_KEY` (секрет, который
«можно не использовать в v1, но читать и не логировать») без заведения
секции в конфиге.

## 2. Запятая в значении default ломает парсинг опций

Опции тега `config` разделяются запятой, экранирования нет. Значит,
невозможен default со списком:

```go
Origins string `config:"CORS_ALLOWED_ORIGINS,default=http://localhost:3000,http://localhost:8080"`
```

— второй кусок станет «опцией». Нужен либо escape (`\,`), либо другой
разделитель опций, либо `default` всегда последней опцией «до конца строки».

## 3. `path` + linux-абсолютный default на Windows

Поле `config:"GATEWAY_ROUTES_PATH,path,default=/etc/gateway/routes.d"`:
в контейнере (linux) default остаётся `/etc/gateway/routes.d`, а на
Windows-машине разработчика тот же default молча превращается в
`<appdir>\etc\gateway\routes.d` — и сервис падает с «каталог маршрутов
не найден». Поведение задокументировано, но для образа, который собирается
под linux, а разрабатывается на Windows, это ловушка.

Идеи: опция `noabs`/`strict-path`, warning в лог при трансформации
«абсолютного» пути в относительный, или оставлять unix-absolute как есть
(файл просто не найдётся — честная ошибка вместо странного пути).

## 4. Не видно, откуда взялось значение

При отладке конфига (не тот источник победил) хочется спросить у viperr,
из какого источника пришло каждое поле: process / env / xml / default.
Например, `viperr.Load` мог бы опционально заполнять отчёт или
`viperr.Explain(&cfg)` печатать таблицу «ключ → значение (секреты маскировать)
→ источник». Для `config print` в CLI сервиса — самое то.

## 5. Мелочь: маркеры ResolveAppDir не расширяемы

`ResolveAppDir` ищет `.env`, `settings.xml`, `settings/settings.xml`.
У gateway ни одного из них может не быть в репозитории (конфиг только из
окружения), и appdir «уезжает» в рабочий каталог. Было бы удобно передать
свой список маркеров (например, `go.mod`, `routes/`) или явный fallback.
